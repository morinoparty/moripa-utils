# Advancement Restore

Advancement Restore は、HuskSync に保存されたスナップショットから、プレイヤーの進捗だけを復元する機能です。
HuskSync の `/userdata restore` はインベントリや体力などを含めてスナップショット全体を復元しますが、このコマンドは進捗だけを差し替え、それ以外のデータは現在のまま残します。

<Callout type="info">
この機能は Paper でのみ動作します。
使用するには、HuskSync を導入する必要があります。`config.conf` の設定は必要ありません。
</Callout>

## コマンド

| コマンド | 権限 | 説明 |
|---------|------|------|
| `/mu advancement restore <プレイヤー> <スナップショット>` | `moripautils.advancement.restore` (デフォルトは OP のみ) | 指定したスナップショットの進捗を、プレイヤーの現在のデータに復元します。 |

- `<プレイヤー>` には、HuskSync にデータが記録されているプレイヤーの名前を指定します。オフラインのプレイヤーも指定できます。Tab キーではオンラインのプレイヤーが補完されます。
- `<スナップショット>` には、スナップショットの ID (UUID) か、新しい順の番号 (最新が `1`) を指定します。
- コンソールからも実行できます。

### スナップショットの補完

`<スナップショット>` を Tab キーで補完すると、そのプレイヤーのスナップショットの ID だけが表示されます。
候補は ID の文字列順に並ぶため、新しい順にはなりません。
候補にカーソルを合わせると、以下の内容が表示されます。

```text
#1 2026-11-14 12:03 / 進捗 123 / DISCONNECT / 固定
```

| 項目 | 説明 |
|------|------|
| 番号 | 新しい順の番号です。最新のスナップショットが `#1` です。 |
| 日時 | スナップショットが保存された日時です。サーバーのタイムゾーンで表示します。 |
| 進捗の数 | レシピの解除を除いた進捗の数です。条件を一部だけ満たした進捗も含みます。進捗のデータが無い場合は `進捗なし` と表示します。 |
| 保存された理由 | HuskSync の保存理由 (`DISCONNECT`、`WORLD_SAVE` など) です。 |
| `固定` | 固定 (pin) されたスナップショットの場合に表示します。 |

番号で指定した場合は、実行者が補完で表示した一覧をもとに解決します。
補完してから実行するまでの間に新しいスナップショットが保存されても、補完で選んだスナップショットが復元されます (補完から 5 分以内の場合)。
補完を使わずに番号を入力した場合や、5 分以上経った場合は、実行時点の一覧で解決します。
実行時には、復元するスナップショットの日時が表示されます。

## 復元の流れ

1. プレイヤーの現在のデータを、固定したスナップショット (保存理由は `MORIPA_ADVANCEMENT_BACKUP`) として保存します。
2. 保存したデータの進捗だけを、指定したスナップショットの進捗に差し替えます。
3. 差し替えたデータを、保存理由 `BACKUP_RESTORE` のスナップショットとして保存します。
4. HuskSync の `/userdata restore` と同じく、Redis にサーバー移動用のデータが残っていれば差し替え、データの更新を通知します。

プレイヤーがオンラインの場合は、HuskSync がすぐに反映します。
オフラインの場合は、次回の参加時に反映されます。

復元前のデータを保存したスナップショットの ID は、実行結果に表示されます (クリックでコピーできます)。
元に戻す場合は、HuskSync の `/userdata restore <プレイヤー> <ID>` で復元してください。
このスナップショットは固定されているため、HuskSync のローテーションで削除されません。不要になったら `/userdata pin` で固定を解除してください。

<Callout type="warn">
進捗は、スナップショットの内容で置き換えられます。
スナップショットに無い進捗は取り消され、スナップショットにある進捗は付与されます。
</Callout>

## 注意事項

- 別のサーバーにいるプレイヤーの場合、HuskSync は Redis を通して現在のデータを取得します。時間内に応答が無い場合は、データベースの最新のスナップショットが復元前のデータとして使われます。
- 別の Minecraft のバージョンで保存されたスナップショットなど、HuskSync が読み込めないスナップショットがあると、一覧を取得できずに失敗することがあります。
- HuskSync の `DataSaveEvent` がキャンセルされた場合など、復元前のデータを 10 秒以内に保存できなかった場合は、復元を中止します。
- オンラインのプレイヤーには、手順 1 で取得したデータ全体 (進捗以外は取得時点のまま) が反映されます。手順 1 から反映までの短い間にインベントリなどが変化した場合、その変化は失われます。
- 手順 3 の保存は固定されないため、通常の保存と同じく HuskSync の `snapshot_backup_frequency` によるローテーションの対象になります。直近 (`snapshot_backup_frequency` 時間以内) の固定されていないスナップショットのうち最も古いものが削除されるため、復元元のスナップショットが削除されることがあります。
