# 設定ファイル

MoripaUtils の設定は、プラグインのデータディレクトリに置かれる `config.conf` にまとめて記述します。
ファイルの形式は [HOCON](https://github.com/lightbend/config/blob/main/HOCON.md) です。
HOCON は JSON の上位互換の書式で、`#` によるコメントや、キーと値の間に `=` を使う書き方、文字列の引用符の省略などが可能です。

| プラットフォーム | 設定ファイルのパス |
|-----------------|-------------------|
| Paper | `plugins/MoripaUtils/config.conf` |
| Velocity | `plugins/moripa-utils/config.conf` |

`config.conf` が存在しない状態でサーバーまたはプロキシを起動すると、デフォルト値を記述したファイルが自動的に生成されます。
設定ファイルに書かれていないキーはデフォルト値で補われるため、変更したい項目だけを記述することもできます。
設定を変更した場合は、[設定の再読み込み](#設定の再読み込み) のコマンドを実行するか、サーバーまたはプロキシを再起動して反映してください。

## 設定の再読み込み

以下のコマンドを実行すると、サーバーやプロキシを再起動せずに `config.conf` を読み込み直せます。
コンソールからも実行できます。

| プラットフォーム | コマンド | 権限 |
|-----------------|---------|------|
| Paper | `/mu reload` | `moripautils.reload` (デフォルトは OP のみ) |
| Velocity | `/muv reload` | `moripautils.reload` |

Velocity には権限のデフォルト値がないため、プレイヤーが `/muv reload` を実行するには LuckPerms などの権限プラグインで `moripautils.reload` を付与してください。

再読み込みでは、最初に新しい `config.conf` を検証します。
内容が不正な場合はエラーの内容を表示し、それまでの設定のまま動作を続けます。
検証に成功した場合は、各機能を停止してから新しい設定で起動し直します。
このとき、メトリクス用の HTTP サーバー、データベースへの接続、MineAuth に登録した HTTP API もすべて作り直されます。

再読み込みには以下の制約があります。

- Prometheus の `*_total` などのカウンターは、再読み込みの時点で 0 に戻ります。Prometheus の `rate()` や `increase()` はリセットを考慮して計算するため、通常は問題になりません。
- Paper の `/ticket` コマンドは、サーバーの起動処理の早い段階 (ブートストラップ) でしか登録できません。起動時に `ticket.enabled` が `false` だった場合、再読み込みで `true` にしてもコマンドは追加されず、サーバーの再起動が必要である旨が表示されます。
- 起動時に `config.conf` の読み込みに失敗してプラグインが無効になった場合は、再読み込みのコマンドも使用できません。設定を修正してからサーバーまたはプロキシを再起動してください。

## デフォルトの設定

Paper で生成されるデフォルトの `config.conf` は以下のとおりです。
生成されるファイルではキーがアルファベット順に並びます。

```text
# MoripaUtils configuration (HOCON)
# https://utils.plugin.morino.party/docs/config
announcement {
    enabled=true
    interval="30 m"
    permission=""
    randomOrder=false
    startupDelay="0 d"
}
database {
    mysql {
        database="moripa_utils"
        host=localhost
        password=""
        port=3306
        properties {}
        user=root
    }
    sqlite {
        file="moripa-utils.db"
    }
    type=sqlite
}
observability {
    enabled=true
    http {
        host="0.0.0.0"
        path="/metrics"
        port=9225
    }
    metrics {
        jvm=true
        samplingIntervalTicks=20
    }
}
server=main
storage {
    accessKeyId=""
    bucket=""
    endpoint=""
    pathStyleAccess=false
    region=us-east-1
    secretAccessKey=""
}
ticket {
    categories=[
        {
            id=protect
            name=土地保護について
        },
        {
            id=grief
            name="荒らし、盗難について"
        },
        {
            id=recovery
            name="アイテム補填、データの復旧"
        },
        {
            id=bug
            name=バグの報告
        },
        {
            id=other
            name=その他
        }
    ]
    enabled=true
    webhook {
        avatarUrl="https://api.mcheads.org/head/{uuid}/64"
        iconUrl="https://raw.githubusercontent.com/morinoparty/moripa-assets/refs/heads/main/logo/logo-72.png"
        url=""
        username="Moripa Utils"
    }
}
```

Velocity では、`server` のデフォルト値が `proxy`、`observability.http.port` のデフォルト値が `9226` になります。
チケット機能、データベース、ストレージは Paper 専用のため、`ticket` ブロック、`database` ブロック、`storage` ブロックは Velocity では使用されません (値の検証は行われます)。
同様に、お知らせは Velocity 専用のため、`announcement` ブロックは Paper では使用されません。

## 共通の項目

| キー | デフォルト | 説明 |
|------|-----------|------|
| `server` | `main` (Paper) / `proxy` (Velocity) | このサーバーを識別する名前です。複数のサーバーを運用している場合に、メトリクスのラベルやチケットの送信元としてサーバーを区別するために使用します。英数字、ハイフン (`-`)、アンダースコア (`_`) のみ使用できます。 |

`server` の値は、Prometheus のメトリクス `minecraft_server_info` (Paper) と `velocity_proxy_info` (Velocity) の `server` ラベルとして公開されます。

## database

`database` ブロックでは、各機能がデータを保存するデータベース (SQLite / MySQL) を設定します。
データベースはプラグイン全体で 1 つで、各機能はその中に機能ごとのテーブルを作成します。
この設定は Paper でのみ使用されます。

| キー | デフォルト | 説明 |
|------|-----------|------|
| `database.type` | `sqlite` | 使用するデータベースの種類です。`sqlite` または `mysql` を指定します。 |
| `database.sqlite.file` | `"moripa-utils.db"` | SQLite のデータベースファイルです。プラグインのデータディレクトリからの相対パスで指定します。 |
| `database.mysql.*` | - | MySQL の接続先 (`host` / `port` / `database` / `user` / `password` / `properties`) です。 |

各項目の詳しい説明と MySQL の設定例は [データベース](/docs/database) を参照してください。

## storage

`storage` ブロックでは、データベースとは別に、ファイルなどを保存する S3 互換のオブジェクトストレージへの接続を設定します。
AWS S3 のほか、Cloudflare R2 や MinIO などの S3 互換ストレージを使用できます。
この設定は Paper でのみ使用されます。

| キー | デフォルト | 説明 |
|------|-----------|------|
| `storage.endpoint` | `""` | 接続先のエンドポイント URL です。`http://` または `https://` から始まる必要があります。空文字の場合は、`storage.region` に対応する AWS S3 のエンドポイントを使用します。 |
| `storage.region` | `us-east-1` | リージョン名です。空にはできません。Cloudflare R2 では `auto` を指定します。 |
| `storage.bucket` | `""` | 使用するバケットの名前です。事前に作成しておく必要があります。 |
| `storage.accessKeyId` | `""` | 認証に使用するアクセスキー ID です。 |
| `storage.secretAccessKey` | `""` | 認証に使用するシークレットアクセスキーです。 |
| `storage.pathStyleAccess` | `false` | バケット名をホスト名ではなく URL のパスに含める (path-style) かどうかです。MinIO などでは `true` にします。 |

`storage.bucket`、`storage.accessKeyId`、`storage.secretAccessKey` のいずれかが空の場合、ストレージは未設定として扱われます。
ストレージは [Schematic](/docs/schematic) 機能のアップロード先として使用されます。

Cloudflare R2 を使用する場合の例は以下のとおりです。

```text
storage {
    endpoint = "https://<ACCOUNT_ID>.r2.cloudflarestorage.com"
    region = auto
    bucket = "moripa-utils"
    accessKeyId = "<ACCESS_KEY_ID>"
    secretAccessKey = "<SECRET_ACCESS_KEY>"
}
```

<Callout type="warn">
`config.conf` にはシークレットアクセスキーが平文で保存されます。ファイルを公開リポジトリなどで共有しないでください。
</Callout>

## observability

`observability` ブロックでは、Prometheus 形式でメトリクスを公開する observability 機能を設定します。

| キー | デフォルト | 説明 |
|------|-----------|------|
| `observability.enabled` | `true` | observability 機能を有効にするかどうかです。`false` にするとメトリクス用の HTTP サーバーは起動しません。 |
| `observability.http.host` | `"0.0.0.0"` | HTTP サーバーが待ち受けるアドレスです。 |
| `observability.http.port` | `9225` (Paper) / `9226` (Velocity) | HTTP サーバーが待ち受けるポートです。 |
| `observability.http.path` | `"/metrics"` | メトリクスを公開する HTTP パスです。 |
| `observability.metrics.jvm` | `true` | JVM / プロセスのメトリクスを公開するかどうかです。 |
| `observability.metrics.samplingIntervalTicks` | `20` | Paper でメインスレッド上のサンプリングを行う間隔 (ティック数) です。`1` 以上を指定する必要があります。 |

各項目の詳しい説明は [Observability の Getting Started](/docs/observability/getting-started) を参照してください。

## ticket

`ticket` ブロックでは、`/ticket` コマンドによるお問い合わせ機能を設定します。
この機能は Paper でのみ動作します。

| キー | デフォルト | 説明 |
|------|-----------|------|
| `ticket.enabled` | `true` | チケット機能を有効にするかどうかです。`false` にするとチケット機能は読み込まれません。 |
| `ticket.categories` | 5 件 (下記参照) | プレイヤーが選択できるお問い合わせのカテゴリーです。記述した順に表示されます。 |
| `ticket.webhook.url` | `""` | 新しいチケットを通知する Webhook の URL です。空文字の場合は通知を行いません。 |
| `ticket.webhook.username` | `"Moripa Utils"` | Webhook の送信者として表示する名前です。 |
| `ticket.webhook.iconUrl` | morinoparty のロゴ | Webhook の送信者として表示するアイコン画像の URL です。 |
| `ticket.webhook.avatarUrl` | `"https://api.mcheads.org/head/{uuid}/64"` | Webhook の Embed に表示するプレイヤーのアイコン画像の URL です。詳しくは [チケットの設定](/docs/ticket/config#discord-webhook) を参照してください。 |

チケットは `database` ブロックで設定したデータベースの `tickets` テーブルに保存されます。

### カテゴリー

`ticket.categories` の各要素は `id` と `name` を持ちます。

| キー | 説明 |
|------|------|
| `id` | カテゴリーを識別する ID です。データベースに保存されるため、運用開始後に変更すると既存のチケットと対応しなくなります。英小文字、数字、ハイフン (`-`)、アンダースコア (`_`) のみ使用でき、カテゴリー間で重複してはいけません。 |
| `name` | プレイヤーに表示されるカテゴリー名です。空にはできません。 |

カテゴリーを 1 件も指定しない場合や、`id` の形式が不正な場合、`id` が重複している場合は、設定ファイルの読み込み時にエラーになり、プラグインは有効化されません。

```text
ticket {
    categories = [
        { id = "bug", name = "バグの報告" }
        { id = "report", name = "プレイヤーの通報" }
        { id = "other", name = "その他" }
    ]
}
```

## announcement

`announcement` ブロックでは、プロキシに接続している全プレイヤーへ定期的にお知らせを送る機能を設定します。
この機能は Velocity でのみ動作します。

| キー | デフォルト | 説明 |
|------|-----------|------|
| `announcement.enabled` | `true` | お知らせを送るかどうかです。 |
| `announcement.interval` | `"30 m"` (30 分) | お知らせを 1 件ずつ送る間隔です。HOCON の期間の書式 (`"30 minutes"`、`"1 h"` など) で指定し、1 秒以上である必要があります。 |
| `announcement.startupDelay` | `"0 d"` (0 秒) | プロキシの起動や設定の再読み込みから、最初のお知らせを送るまでの時間です。 |
| `announcement.randomOrder` | `false` | お知らせをランダムな順番で送るかどうかです。 |
| `announcement.permission` | `""` | お知らせを受け取るのに必要な権限です。空文字の場合は全プレイヤーが受け取ります。 |

送るメッセージは `config.conf` ではなく、メッセージファイルに記述します。詳しくは [お知らせ](/docs/announcement) を参照してください。

## 設定の検証

設定ファイルの読み込み時には、HOCON の構文と各項目の値が検証されます。
構文に誤りがある場合や、値が条件を満たさない場合は、起動ログに設定ファイルのパスとエラーの内容が出力され、プラグインは有効化されません。
誤った設定のまま黙ってデフォルト値で動作することを避けるため、この挙動になっています。
