# Ticket

Ticket は、プレイヤーがゲーム内から運営へお問い合わせを送信するための機能です。
プレイヤーが `/ticket` を実行するとお問い合わせ用の画面 (Dialog) が開き、カテゴリーを選んで内容を入力すると送信されます。
送信されたお問い合わせは「チケット」としてデータベース (SQLite または MySQL) に保存され、運営に通知されます。

<Callout type="info">
この機能は Paper でのみ動作します。Velocity では `config.conf` の `ticket` ブロックは使用されません。
</Callout>

## 送信の流れ

1. プレイヤーが `/ticket` を実行すると、お問い合わせ用の Dialog が表示されます。
2. Dialog でカテゴリーを選択し、お問い合わせ内容を入力して「送信」を押します。
3. 入力内容が検証され、問題がなければチケットとしてデータベースに保存されます。
4. 送信したプレイヤーには、チャットでチケット番号 (例: `#12`) が伝えられます。
5. 通知権限を持つオンラインのプレイヤーと、設定されている場合は Discord Webhook に新しいチケットが通知されます。

入力内容には次の制限があります。

| 項目 | 制限 |
|------|------|
| カテゴリー | `config.conf` の `ticket.categories` に存在するカテゴリーのみ選択できます。 |
| 内容 | 空にはできません。前後の空白は取り除かれ、最大 1000 文字まで入力できます。 |

入力に誤りがあった場合はチケットは保存されず、チャットで理由が伝えられます。
送信ボタンは 1 回だけ有効なため、やり直す場合は再度 `/ticket` を実行してください。
Dialog を開いてから 30 分が経過すると、その Dialog からは送信できなくなります。

## コメント

送信されたチケットには、送信したプレイヤー本人と運営がコメントを書き込めます。
コメントはチケットごとに書き込まれた順に保存され、運営とプレイヤーのやり取りに使用できます。
状態が `CLOSED` のチケットにもコメントを書き込めます。

| 書き込む人 | 対象のチケット | 立場 |
|-----------|--------------|------|
| 送信したプレイヤー本人 | 自分が送信したチケット | `PLAYER` |
| `moripautils.ticket.staff` 権限を持つプレイヤー | すべてのチケット | `STAFF` (自分が送信したチケットでは `PLAYER`) |

ゲーム内では `/ticket comment <番号>` でコメント入力用の Dialog が開き、`/ticket view <番号>` でチケットと最新 10 件のコメントがチャットに表示されます。
コメントの内容には、お問い合わせの内容と同じく最大 1000 文字の制限があります。
存在しないチケットや、閲覧する権限のないチケットを指定した場合は、どちらも「お問い合わせが見つかりません。」と表示されます。
Web などからコメントを扱う場合は [MineAuth 連携](/docs/ticket/mineauth) を参照してください。

## コマンド

| コマンド | 権限 | 説明 |
|---------|------|------|
| `/ticket` / `/ticket create` | `moripautils.ticket.use` | お問い合わせ用の Dialog を開きます。プレイヤーのみ実行できます。 |
| `/ticket view <番号>` | `moripautils.ticket.use` | チケットと最新 10 件のコメントをチャットに表示します。本人のチケットのみ表示でき、`moripautils.ticket.staff` 権限を持つ場合はすべてのチケットを表示できます。 |
| `/ticket comment <番号>` | `moripautils.ticket.use` | コメント入力用の Dialog を開きます。書き込める範囲は `/ticket view` と同じです。 |
| `/ticket list [ページ] [--status <状態>] [--player <名前>]` | `moripautils.ticket.use` | 閲覧できるチケットを新しい順に 1 ページ 10 件ずつ表示します。各行をクリックすると `/ticket view` で詳細が開きます。ページ番号を省略した場合は 1 ページ目を表示します。絞り込みについては [一覧の絞り込み](#一覧の絞り込み) を参照してください。 |
| `/ticket close <番号> [--reason-type <理由>]` | `moripautils.ticket.use` | チケットをクローズします。本人のチケットのみクローズでき、`moripautils.ticket.staff` 権限を持つ場合はすべてのチケットをクローズできます。理由については [クローズと再オープン](#クローズと再オープン) を参照してください。 |
| `/ticket reopen <番号>` | `moripautils.ticket.staff` | クローズされたチケットをオープンに戻します。 |
| `/ticket teleport <番号>` (`/ticket tp`) | `moripautils.ticket.staff` | チケットが送信された場所へテレポートします。このサーバーで送信されたチケットのみ対象です。 |

`<番号>` は Tab キーで補完できます。
候補には、実行したプレイヤーが閲覧できるチケット (本人のチケット、`moripautils.ticket.staff` 権限を持つ場合はすべてのチケット) の番号だけが、新しい順に最大 30 件表示されます。
`/ticket close` ではオープン中のチケット、`/ticket reopen` ではクローズされたチケットだけが候補になります。

`/ticket view` で表示されるチケットには、`[コメントする]` / `[クローズ]` / `[再オープン]` / `[テレポート]` のうち、実行できる操作のボタンが付きます。

### 一覧の絞り込み

`/ticket list` では、次のフラグで表示するチケットを絞り込めます。
ページ移動のボタンには、指定した絞り込みが引き継がれます。

| フラグ | 説明 |
|-------|------|
| `--status <open \| closed>` | 対応状況で絞り込みます。 |
| `--player <名前>` | 送信時点のプレイヤー名で絞り込みます (大文字と小文字は区別しません)。`moripautils.ticket.staff` 権限を持つ場合のみ指定できます。 |

```text
/ticket list --status open
/ticket list 2 --status closed --player _NIKOMARU
```

### クローズと再オープン

`/ticket close` では、`--reason-type` でクローズする理由を指定できます。
省略した場合は `done` になります。

| 理由 | 表示 | 説明 |
|------|------|------|
| `done` | 対応完了 | 対応が完了しました。 |
| `not-planned` | 対応しない | 対応しないことにしました。 |
| `duplicate` | 重複 | 他のチケットと重複しています。 |

```text
/ticket close 12 --reason-type not-planned
```

クローズされたチケットは、`moripautils.ticket.staff` 権限を持つプレイヤーが `/ticket reopen` でオープンに戻せます。
送信したプレイヤー本人は、自分のチケットをクローズできますが、再オープンはできません。
クローズされたチケットにも、引き続きコメントを書き込めます。

## 権限

| 権限 | デフォルト | 説明 |
|------|-----------|------|
| `moripautils.ticket.use` | 全員 | `/ticket` でお問い合わせを送信できます。 |
| `moripautils.ticket.notify` | OP | 新しいチケットの送信や、プレイヤーからのコメントをチャットで通知されます。 |
| `moripautils.ticket.staff` | OP | すべてのチケットを閲覧し、運営としてコメントを書き込めます (ゲーム内 / MineAuth の HTTP API)。すべてのチケットのクローズと再オープン、送信場所へのテレポート、`/ticket list --player` も行えます。 |

## 通知

新しいチケットが送信されると、次の通知先に通知されます。
通知に失敗した場合でもチケットの保存は完了しており、失敗の内容はサーバーのログに記録されます。

- `moripautils.ticket.notify` 権限を持つオンラインのプレイヤーへのチャットメッセージ
- `ticket.webhook.url` に設定された Discord Webhook (未設定の場合は送信しません)

Discord Webhook には、チケット番号・プレイヤー・サーバー・送信時のワールドと座標・カテゴリー・内容を含む Embed が送信されます (形式は [設定](/docs/ticket/config#送信される-embed) を参照してください)。
内容に `@everyone` などが含まれていてもメンションは発生しません。

コメントが書き込まれた場合は、書き込んだ人の立場によって通知先が変わります。

| 書き込んだ人 | 通知先 |
|-------------|--------|
| 送信したプレイヤー本人 (`PLAYER`) | `moripautils.ticket.notify` 権限を持つオンラインのプレイヤー (書き込んだ本人を除く) と Discord Webhook |
| 運営 (`STAFF`) | チケットを送信したプレイヤー (オンラインの場合のみ) |

チケットがクローズ / 再オープンされた場合は、変更した人によって通知先が変わります。

| 変更した人 | 通知先 |
|-----------|--------|
| 送信したプレイヤー本人 | `moripautils.ticket.notify` 権限を持つオンラインのプレイヤー (変更した本人を除く) と Discord Webhook |
| 運営 | チケットを送信したプレイヤー (オンラインの場合のみ) と Discord Webhook |

チャットの通知には、`/ticket view` を実行する `[表示]` ボタンが付きます。
データベースを複数のサーバーで共有している場合でも、ゲーム内の通知はコメントが書き込まれたサーバーにいるプレイヤーにのみ届きます。
MineAuth の HTTP API から書き込まれたコメントは、MineAuth が導入されているサーバーで通知されます。
オフラインのプレイヤーには、次回のログイン時にも通知されません。

## データの保存先

チケットは、プラグイン全体で共有するデータベースの `tickets` テーブルに、コメントは `ticket_comments` テーブルに保存されます。
デフォルトでは、プラグインのデータディレクトリにある SQLite データベース (`plugins/MoripaUtils/moripa-utils.db`) が使用されます。
MySQL への切り替えについては [データベース](/docs/database) を参照してください。
