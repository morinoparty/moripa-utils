# 設定

チケット機能の設定は、`config.conf` の `ticket` ブロックに記述します。
設定ファイル全体の構成は [設定ファイル](/docs/config) を参照してください。
設定を変更した場合は、`/mu reload` を実行するか、サーバーを再起動して反映してください (詳しくは [設定の再読み込み](/docs/config#設定の再読み込み) を参照してください)。

## デフォルトの設定

```text
ticket {
    categories=[
        {
            id=protect
            name=土地保護について
        },
        {
            id=grief
            name="荒らし、盗難について"
        },
        {
            id=recovery
            name="アイテム補填、データの復旧"
        },
        {
            id=bug
            name=バグの報告
        },
        {
            id=other
            name=その他
        }
    ]
    enabled=true
    webhook {
        avatarUrl="https://api.mcheads.org/head/{uuid}/64"
        url=""
    }
}
```

## 設定項目

| キー | デフォルト | 説明 |
|------|-----------|------|
| `ticket.enabled` | `true` | チケット機能を有効にするかどうかです。`false` にすると `/ticket` コマンド、データベースへの接続、MineAuth の HTTP API はいずれも登録されません。 |
| `ticket.categories` | 5 件 (下記参照) | Dialog に表示するカテゴリーです。記述した順に表示され、先頭のカテゴリーが初期選択になります。 |
| `ticket.webhook.url` | `""` | 新しいチケットを通知する Discord Webhook の URL です。空文字の場合は通知を行いません。 |
| `ticket.webhook.avatarUrl` | `"https://api.mcheads.org/head/{uuid}/64"` | Embed に表示するプレイヤーのアイコン画像の URL です。`{uuid}` はプレイヤーの UUID に、`{name}` はプレイヤー名に置き換えられます。空文字の場合はアイコンを表示しません。 |

チケットの保存先は、プラグイン全体で共有する `database` ブロックで設定します。
SQLite / MySQL の切り替えなどは [データベース](/docs/database) を参照してください。

## カテゴリー

デフォルトでは、次の 5 件のカテゴリーがこの順に表示されます。

| `id` | `name` |
|------|--------|
| `protect` | 土地保護について |
| `grief` | 荒らし、盗難について |
| `recovery` | アイテム補填、データの復旧 |
| `bug` | バグの報告 |
| `other` | その他 |

各カテゴリーは `id` と `name` を持ちます。

| キー | 説明 |
|------|------|
| `id` | データベースに保存される識別子です。英小文字・数字・ハイフン・アンダースコアのみ使用できます。 |
| `name` | Dialog や通知に表示される名前です。空にはできません。 |

`id` はチケットとともにデータベースへ保存されます。
既存のカテゴリーの `id` を変更すると、変更前に送信されたチケットとカテゴリーの対応が失われるため注意してください。
カテゴリーを削除した場合も既存のチケットは残りますが、HTTP API の `categoryName` は `null` になります。

## Discord Webhook

Discord のチャンネル設定から Webhook を作成し、その URL を `ticket.webhook.url` に設定します。

```text
ticket {
    webhook {
        url = "https://discord.com/api/webhooks/xxxxxxxx/yyyyyyyy"
    }
}
```

### 送信される Embed

新しいチケットと、プレイヤーからのコメントが Embed として送信されます。
Embed は次の要素で構成されます。

| 要素 | 新しいチケット | コメント |
|------|---------------|---------|
| 作成者 (上部) | 送信したプレイヤーの名前とアイコン | コメントを書き込んだ人の名前とアイコン |
| タイトル | `Ticket Created - #<チケット番号>` | `Ticket Commented - #<チケット番号>` |
| 本文 | チケットの情報 (下記) | チケットの情報 (下記) |
| `MESSAGE` | お問い合わせの内容 | コメントの内容 |
| フッター | `Created by <プレイヤー名>` と送信日時 | `Commented by <名前>` と書き込み日時 |

チケットの情報は、送信したプレイヤーの UUID、送信元のサーバー、送信時にいたワールドと座標、カテゴリーをコードブロックで表示します。

```yaml
UUID: f8b761ec-4a54-48eb-a040-c5604042bcc9
Server: main
World: world_nether
Location: X: 415, Y: 32, Z: 362
Category: 荒らし、盗難について
```

### アイコン画像

アイコン画像の URL は `ticket.webhook.avatarUrl` で変更できます。
デフォルトでは [MC Heads](https://mcheads.org/) の頭部画像を、名前の変更に影響されない UUID で取得します。

```text
ticket {
    webhook {
        url = "https://discord.com/api/webhooks/xxxxxxxx/yyyyyyyy"
        # プレイヤー名で取得する場合
        avatarUrl = "https://api.mcheads.org/head/{name}/64"
    }
}
```

サービストークンからのコメントなど、UUID を持たない書き込みで `{uuid}` を使用している場合は、アイコンを表示しません。

Webhook の送信は 10 秒でタイムアウトします。
送信に失敗した場合やエラーの応答が返った場合は、サーバーのログに警告が記録されます。

## 起動時の動作

チケット機能に関する設定は、サーバーの起動処理の早い段階 (ブートストラップ) と、プラグインの有効化時の 2 回読み込まれます。
`/ticket` コマンドはブートストラップの段階で登録されるため、`ticket.enabled` を `false` から `true` に変更した場合はサーバーの再起動が必要です。
`true` から `false` への変更は `/mu reload` でも反映され、コマンドは残りますが、実行するとお問い合わせを受け付けていない旨が表示されます。
`config.conf` の内容が不正な場合は、コマンドを登録せずに起動処理を続け、プラグインの有効化時にエラーとして停止します。
